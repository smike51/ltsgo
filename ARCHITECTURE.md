# LTSGO — архитектура

Образец — onpoint.casa (`..\onpoint-casa\ARCHITECTURE.md`). Здесь — только то, что отличается.

## 1. База
- Postgres (`pgvector/pgvector:pg16`) в своём контейнере на starpom-app, каталог `/opt/ltsgo/kb`.
  Бэкап — до запуска. Выкладку делает «Релиз»/«Инфра».
- Единственный, кто пишет в базу, — сервис `ltsgo-kb` (Node, порт рядом с :8095). Сайт, агенты и n8n — только через API.
- Схема — `kb/migrations/001_init.sql`:
  - **текст:** `books → book_texts (издание/перевод) → passages (письмо/глава)`;
  - **маршрут:** `journeys (путешественник) → stops (место, даты, транспорт, фрагменты текста)`;
  - **сущности:** `entities` (люди, места, здания, события, картины) с Wikidata-id и историческими названиями,
    связи `entity_links` (встретил, жил в, видел);
  - **знание:** `facts` со слоем `then | now | go`, классом (как часто перепроверять), статусом и цитатой;
  - **витрина:** `quotes`, `media` (тогда/сейчас/реконструкция, лицензия, пометка ИИ), `offers` (партнёрские);
  - **контроль:** `change_proposals`, `fact_history`, `alerts`, `agent_runs`, `sources`, `source_snapshots`.
- Несколько путешественников в одной книге — несколько `journeys` (Фогг и Нелли Блай на одной карте).
- Даты — в календаре путешествия (`julian` для русских до 1918), сайт показывает оба.

## 2. Конвейер одной книги
1. **Текст:** скачать свободное издание (Викитека, Gutenberg, Gallica, Internet Archive) → `book_texts`
   → разбить на `passages` (письма/главы/абзацы). Код, без модели.
2. **Извлечение:** haiku по фрагментам → предложения: остановки, люди, места, здания, события, цитаты.
   Каждое — с дословной цитатой; код проверяет, что цитата есть во фрагменте.
3. **Привязка:** код ищет каждую сущность в Wikidata (поиск + тип + даты + координаты); неоднозначное — человеку.
4. **Обогащение:** из Wikidata/Википедии (ru/en) — даты, координаты, краткая биография, «чем знаменит»;
   статус `verified_wiki` только когда совпали два источника.
5. **Медиа:** Commons → Europeana/Gallica/музейные API: гравюры и портреты эпохи, современные фото.
   Только PD/CC, лицензия обязательна.
6. **Эпоха:** события за годы путешествия в странах маршрута (Wikidata) → таймлайн.
7. **Сейчас и поехать:** сохранность, что на месте сейчас, часы, транспорт, отели/экскурсии рядом.
8. **Ревью** владельцем: экран предложений (образец onpoint `review.html`).
9. **Тексты для сайта:** sonnet пишет главы из утверждённого; перевод ru↔en; утверждение.

Шаг 2–7 — задания `crawl/TASK-*.md`, по одной книге/главе на агента, результат только в API.

## 3. Сайт
- Astro, PWA (офлайн-кэш маршрута, геолокация «рядом с вами»), ru/en.
- **Карта/глобус (решение владельца 15.11.2026):** не cobe (как в onpoint — слишком схематичный), а
  **детальная физическая карта** с рельефом, горами и морями + **политический слой того времени**.
  - Основа: MapLibre GL (режим глобуса) + рельеф (DEM-тайлы, hillshade) + физическая подложка
    (Natural Earth: рельеф, батиметрия, реки) — без современных границ.
  - Исторические границы: векторные слои по годам путешествия (1789–1790 для Карамзина, 1852–1855
    для Гончарова). Кандидаты-источники: historical-basemaps (aourednik, открытая лицензия), CShapes
    (с 1886), Euratlas/старинные карты для сверки; недостающее рисуем сами — каждый слой с источником.
  - Поверх — маршрут, остановки, старинные карты (David Rumsey / Allmaps) как прозрачный слой.
  - В базе: границы эпохи — сущности `kind = polity` с геометрией и годами (добавить в миграцию 002).
- Страницы: книга → маршрут (карта-история) → остановка (тогда / сейчас / поехать) → место / человек / событие.
- Сайт не хранит знание: `sync` забирает из API только утверждённое.
