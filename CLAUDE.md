# LTSGO — литературный трэвел-гид

Общие правила — `C:\Users\admin\OneDrive\dev\CLAUDE.md`. Образец всего устройства — onpoint.casa
(skill `kb-site-builder`, папка `..\onpoint-casa`). Отвечать по-русски, коротко.

## Где что
- `PROJECT_PLAN.md` — что строим, для кого, принципы, фазы, открытые решения.
- `ARCHITECTURE.md` — устройство базы, конвейер книги, сайт.
- `refs/books-catalog.md` — каталог книг (84), линейки маршрутов, первая волна.
- `kb/migrations/` — схема Postgres. Пишет в базу только сервис `ltsgo-kb` (через API).
- `texts/` — тексты книг (raw, чистый текст, фрагменты, SOURCE.md); `tools/` — скрипты обработки.
- `crawl/` — задания агентам (`TASK-*.md`), появятся в фазе 2.
- Память проекта: `..\_brain\memory\ltsgo_project.md`.

## Правила проекта
1. Факт без источника и дословной цитаты — не проверенный. Статусы: `verified_source` ✅,
   `verified_wiki` ✅ (сверено с Wikidata/Википедией), `book_only` 📖, `unverified` ❓, `disputed`, `obsolete`.
2. Агенты и модели пишут только предложения (`change_proposals`), утверждает человек.
3. Текст книги берём только из общественного достояния; переводы — свободные старые или свои (помечены).
   Для книг под охраной — только факты и цитаты до 15 слов.
4. У каждой картинки — лицензия, автор, источник. ИИ-материалы помечаются `ai_generated`.
5. Даты старого стиля хранятся с календарём (`julian`/`gregorian`), на сайт — оба.
6. Ничего не зашивать под одну книгу: всё через таблицы `books / journeys / stops / entities`.
7. Секреты — только `..\_private\` или «Ключи», никогда в git.
